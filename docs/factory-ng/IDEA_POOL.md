## Refactor root-cause analysis

Question: when a small refactor candidate keeps recurring, could a later,
read-only analysis connect it to a model profile, Skill, contract, or prior
change?

Keep this as an idea only. It does not run at 02:00, does not create tickets,
does not change contracts, and does not attribute blame to a model. Revisit
only after the ordinary Factory flow is running and there is real evidence to
analyse.
